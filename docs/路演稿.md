## 0:00–0:15　一句话说清是什么

「这是一个无障碍科普游戏《可及》。你是工业设计大二学生，接了一个期末作业：让校园图书馆对轮椅真正可用。你要做三个决定——但每个决定都有代价。」

（**同步动作**：投屏显示游戏首页，手指放在选项上）

## 0:15–0:50　现场走一次选择（真玩，不放视频）

「我先量尺寸，不直接改造。」→ 点击第一个选项。

「注意左上角三条：**项目进度 / 当事人信任 / 可持续性**。我选了最踏实的一步，信任涨得最快。」

走到第二个选择点：「现在是我最想说的一句——**障碍来自环境和设计，不来自人**。所以这里没有『我替你决定』的选项，只有『谁参与设计、代价谁来承担』。」

## 0:50–1:20　展示结局卡 + 科普档案（这是差异点）

「通关后不是一句『任务完成』，而是把三个决定**回放**给你看，并告诉你这个世界变成了什么样。」

按 **Tab** 打开档案库 → 点开一条 → 展示来源链接：

「游戏里每一条科普——坡度 1:12、《无障碍环境建设法》、盲道、辅具——**都带来源，点得开、查得到**。科普不能靠我一张嘴。」

## 1:20–1:50　立意 + 技术一句

「市面上很多助残产品讲的是『我帮你』；我想做的是让玩家亲身体验一次**选择的代价**，而不是被教育。」

「技术上它就是一个单文件网页，localhost 直接跑，零依赖、可离线——评委老师现在上手点两下就能玩。」

## 1:50–2:00　收尾

「《可及》，取自『每个人都能到达』。谢谢。」

## 备答（评委可能问）

**Q1：为什么做成游戏，不做工具？**（最可能被问）
A：工具解决「这一处能不能用」，游戏解决「为什么有人觉得无障碍与我无关」。赛题三个方向里，老龄/残障的**认知鸿沟**比技术鸿沟更难填，游戏是最便宜的共情手段。

**Q2：数据是真的吗？**
A：剧本里的原则性数据（坡道坡度 1:12、台阶高度、法条名称与生效日期、盲道规范）全部来自公开标准与官方法规，档案库里每条都列了来源 URL 可点开核对；具体场景（某市图书馆）是**为教学做的模拟样例**，不是伪造的实地数据——比赛也明确鼓励用公开/模拟数据（`00_contest_brief.md` §5）。

**Q3：TRAE 做了什么？**
A：TRAE 完成了网页版构建脚本 `web/build_web.py` 并实跑自检（读回字节数 26297、剧情/结局/档案文本命中、无占位符残留），产物就是现场演示的 `web/index.html`。过程截图与关键步骤已在 `evidence/` 存档。
