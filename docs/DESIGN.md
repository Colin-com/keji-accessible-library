# 设计文档 v2 · 无障碍科普叙事游戏

> 2026-10-11 转向：从「力学知识解谜」改为「无障碍帮助 + 底特律式分支叙事」。v1（物理力学图解）作废。

## 一句话

一个大学生用自己专业的本事，帮残障人士解决真实的无障碍难题；从一件小事长成一个真正做成的项目。
**玩家自选专业、自选解决方法**，选择有后果，结局多样。

## 核心价值（内容红线，先于一切）

1. **社会模式优先**：障碍来自环境、工具与设计的失配，不来自人的缺陷。写残障角色时，禁止"身体出问题→需要被修好"的框架。
2. **Nothing about us without us**：残障角色有自己的目标、判断和能动性，不是被动等待救援的道具。他们可以拒绝你的"好意"。
3. **拒绝怜悯叙事与说教**：不用悲情音乐、不用"你真了不起"式的感动。价值观只通过**后果、关系变化、他人的生活变化**呈现。
4. **事实可溯源**：任何知识、法规、技术、数据都必须有出处（URL/标准编号/法条）。说教可以免，事实错误不能有——这是科普游戏的生命线。
5. **不美化也不灾难化**：既有能解决的，也有解决不了/代价很大的；不把无障碍包装成"一举成功的英雄故事"（这恰恰是现实里最假的一种叙事）。

## 玩法支柱

| 支柱 | 含义 |
|-|-|
| 专业自选 | 不同专业 = 不同的解题工具箱。不是换皮：同一问题，软件、工业设计、康复、社工的**可行解不同、代价不同、被谁接受也不同** |
| 解法自选 | 每个案例至少 **3 条可行路线**（技术 / 沟通协作 / 制度倡导 三类），都合法可行，但有代价与副作用 |
| 分支与后果 | 底特律式：选择改变关系值、项目进度、后续可用资源与最终结局 |
| 科普载体 | **无障碍档案库**（图鉴）：随剧情解锁现实世界的辅助技术、标准法规、真实案例与设计原则 |

## MVP 垂直切片（只做这一个，5–10 分钟，网页版可玩）

- **1 个案例**（待定：校园在线选课系统？图书馆？公交站台？）、**2 个专业可选**、**3 条解法**、**2 个结局**（解决 / 部分解决并付出代价）
- 1 组档案库解锁条目（含真实来源）
- 验收标准：
  1. 技术链通（headless 导入 + Web 导出可玩）
  2. **分支可达性自动测试**：脚本穷举所有选择组合，确认每条路径都能抵达结局、无死节点、无悬空引用
  3. 关键事实与出处逐条核对
  4. 价值观检查：至少过一遍"怜悯叙事 / 医学模式 / 说教"三条红线复查

## 技术架构

- Godot **4.7.2**（已就位 `.tools/godot/`），`gl_compatibility`，640×360 canvas_items，像素风
- **自研剧情引擎**（不用 Dialogic，alpha 风险 + 依赖编辑器 GUI）：`res://game/story/` 数据驱动
  - `case_*.json`：节点图（对话 / 选择 / 条件 / 效果）+ 状态机（flags、关系值、项目进度）
  - 多 agent 可并行写作（每案例一个数据包）
- 自动测试：headless 跑 GDScript 测试，**穷举所有选择组合**遍历剧情图
- 导出：Web（index.html + wasm），本地 `python -m http.server` 预览

## 内容生产线（多 agent）

- **调研底座**（ana 分身）→ `E:\Claw-Data\learn\accessibility\`：WCAG/国标、辅助技术清单、法规（如《无障碍环境建设法》）、真实案例、社会模式论述。**全部带来源。**
- 剧本：数据驱动 JSON，逐案例派活（每案例独立数据包，可并行）
- 美术：占位色块先行，后期替换（美术来源：CC0 素材 / img 分身生成 / 手绘）
